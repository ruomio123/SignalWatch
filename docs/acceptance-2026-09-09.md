## 实际运行与浏览器验收

以下 11 组端到端场景通过：

1. API 连接真实 MySQL 和隔离 Redis，`/readyz` 返回正常。
2. 真实 CLI 授权/撤权、最后一个 operator 保护；同一 JWT 即时切换业务/运维访问权限。
3. 公开注册拒绝 `role` 注入。
4. 浏览器注册、确认密码校验、自动登录、时区与摘要时间持久化。
5. 双 Worker 启动，Bootstrap → UPSERT → Matcher 完成确认 → checkpoint。
6. 新订阅本地回填、跨订阅论文去重、完整摘要/作者和多订阅匹配原因展示。
7. 真实 SMTP 邮件正文、跨订阅投递标记、双 Worker 同日只发一封。
8. 真实 Redis 多 Worker 心跳、来源统计、成功尝试与 current checkpoint；运维响应不含凭证。
9. 浏览器编辑、暂停、重新启用、软删除订阅。
10. 移动端无横向溢出、未登录访问受保护页跳转、重新登录；无浏览器脚本异常。
11. Worker 正常退出后的 stopped 状态、有效 checkpoint 启动跳过采集、Recovery 重放不重复论文或邮件。

最终前端文案更新后重新编译 API，再次通过上述场景。

## 验收边界

- 真实 Search/Feed 的基础 HTTP 检查均返回 200；正式 Feed 客户端成功解析 860 个论文 ID，
  正式 Search 客户端随后收到 429 限流。
  确定性端到端验收不依赖外部服务实时状态，不能替代真实来源的长期运行观察。
- Collector/Digest 锁采用固定 TTL、不续租；超过 TTL 的任务不保证跨 Worker 互斥。
- SMTP 已接收但数据库投递标记失败时可能重复发送；SMTP 接收不等同于收件方最终送达。
- 当天无候选后完成标记生效，新到论文留到下一天。
- 不包含生产压测、长期运行、用户反馈、LLM 或自然语言订阅助手验收。

部署当前版本前，应先在目标环境执行迁移 00011，再启动 API/Worker 并授权运维账号。
