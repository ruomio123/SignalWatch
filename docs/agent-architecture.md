# Agent 架构与运维

## 产品与模块边界

订阅页的「AI 创建订阅」和论文详情的「AI 全文对话」共用持久会话与运行状态机。模型通过 JSON 动作协议决定澄清、查询工具、生成草案或回答。订阅最多一个分类，关键词为 OR；只有用户确认草案才能创建订阅。工具只能调用既有业务接口，不能执行 SQL、命令或任意 URL。

`internal/agent` 编排运行、上下文和证据检查；`internal/document` 管理文档版本、分段与 BM25 检索；`internal/platform/document` 实现 arXiv 下载和 Poppler 进程。启动层负责装配。API 只提交和读取任务，Agent 与文档执行器在 Worker 独立运行，普通邮件路径不等待它们。

## 凭据与默认模型

每位用户可保存多条具名凭据，同一家供应商的条目彼此独立。`is_default` 与唯一生成槽约束保证每用户最多一个默认配置。迁移 00027 保留已有密文、generation、revision 和 AAD 字段，不要求用户重新输入 Key。

旧 `/ai/configuration` 接口管理默认配置，新 `/ai/credentials/:id` 管理指定凭据。改用已经保存的其他供应商通过 `/ai/default-selection` 完成。替换默认供应商时保留原供应商凭据；已有目标凭据需要使用默认选择接口，避免隐式覆盖。聊天临时模型不会修改保存的模型，解密始终使用保存时的 AAD。配置修订计数器仍按用户递增，删除后不会复用版本。

删除非默认凭据不影响邮件；删除默认凭据关闭既有 AI 开关。聊天无默认凭据时仍可选择其他可用凭据。跨供应商上下文传递在对话界面明确说明。密钥只在必要的模型调用边界解密；日志不包含原始提示词、密钥或供应商响应正文。

## 运行与恢复

每会话最多一个活动运行。提交由 `(conversation_id,idempotency_key)` 去重，相同键不同请求返回冲突。运行最多 4 次模型调用、3 次工具执行、180 秒，模型单次最多 30 秒。用户并发限制和冷却沿用统一 CallRunner；等待调用名额也计入时间预算。日限额按实际模型调用计数。

MySQL 保存状态与检查点，30 秒租约每 2 秒续租，并通过 epoch 拒绝旧执行者写回。调用前持久化 `calling`；校验成功后持久化 `action`，已保存动作可以恢复。重启发现 `calling` 时结果标为 unknown，不自动重放付费请求。远端模型与本地数据库无法原子提交，无法确定结果时保守终止。

草案确认的账户锁、会话锁、草案版本校验、订阅插入、回填入队和确认登记在订阅命令事务内完成。重复确认返回同一订阅。编辑草案递增版本，旧版本不可确认。删除会话级联删除消息、运行、步骤和草案；已创建订阅保留。

运行步骤记录 call_id、供应商调用 token、工具名、耗时和错误码。通过 `/agent/runs/:id` 与 `/ai/calls` 查看执行，不保存隐藏思维链。普通账号只能读取自己的记录。

## 全文边界

Worker 主机需安装 `pdftotext`、`pdfinfo`（Poppler）和 `prlimit`（util-linux）。缺失或解析失败会显示全文不可用，用户可切换摘要模式，普通功能继续工作。

用户再次提交全文问题时，会重新排队准备该版本此前失败的文档；已就绪或正在准备的文档继续复用。后台不会自行循环重试失败文档，也不会因此重放付费模型调用。

PDF 仅按需从固定 arXiv 来源下载；版本化地址从受校验的论文标识构造。历史无版本链接先读取元数据，更新时间匹配后才下载固定版本。请求使用共享 arXiv 限速器，禁止重定向，不接受客户端 URL。

最大 25 MiB、200 页、4 MiB 提取文字；解析子进程限制 512 MiB 地址空间、25 秒 CPU、30 秒墙钟时间、文件大小和打开文件数。工作目录临时创建并清理，不提供 PDF 镜像。

分段不跨页，每段最多 600 个词，重叠 80 词。BM25 查询限定单文档；默认读取四个匹配片段及最多两个相邻片段。中文问题由 Agent 生成英文检索词。文档身份含来源更新时间、PDF URL、解析器版本；就绪文档记录固定 arXiv 版本、内容哈希。引用绑定文档、页码、原文片段和版本化链接；写回答时再次检查当前论文版本。

只支持可提取文字；双栏阅读顺序、复杂表格、公式和扫描件可能无法可靠表达。证据校验验证引用存在，不等同于验证全部语义。没有相关证据时应明确说明资料不足。

## 发布与验收

1. 在隔离测试库应用 00027–00029，运行 `scripts/verify.sh` 和 `scripts/test-migrations.sh`。
2. 在 Worker 主机安装上述 PDF 工具，并确认命令可用。
3. 停止 API/Worker，备份数据库和 AI 主密钥；应用新增迁移，同步发布 API、Worker 和内嵌前端。
4. 检查普通订阅、普通邮件、旧摘要入口，再验收新对话。回退凭据结构使用已验证备份，不执行破坏性 Down。

`AI_SUBSCRIPTION_AGENT_DAILY_LIMIT` 与 `AI_PAPER_QA_DAILY_LIMIT` 默认 0，表示不限。两个维度都按 UTC 日、实际供应商调用计数。固定预算依旧限制每轮最大调用数。

## API 管理与具名凭据（迁移 00029）

`/settings` 仅展示阅读偏好；侧栏 `/api-keys` 管理供应商凭据，列表展示名称、供应商与模型、脱敏 Key、创建及上次使用时间。创建、编辑、删除使用独立弹窗；用量与诊断位于第二个标签页。

凭据身份复用已有 `generation`，作为公开 `id` 和数据库主键 `(user_id,generation)`。同一供应商可保存多条；迁移不改既有 generation、配置版本、密文字节、nonce 或默认标记。默认约束通过生成列的唯一索引保证每用户最多一条默认。配置版本仍按用户单调递增，AES-GCM AAD 继续使用保存时的供应商、模型和版本。

`POST /api/v2/ai/credentials` 创建独立条目；`GET/PUT/DELETE /api/v2/ai/credentials/:id` 和 `POST .../:id/test` 操作具体条目，修改与删除要求对应 ETag。编辑可改变名称、模型或密钥，供应商保持不变；添加另一家供应商使用新建入口。旧单配置 `/ai/configuration` 继续指向默认条目。

Agent 提交新增 `credential_id`；运行继续绑定该 generation 与配置版本，后续调用按身份读取，不会退回同厂商其他 Key。旧的不带身份的提交只在该供应商凭据唯一时兼容，否则返回冲突。新增凭据不覆盖旧条目；首次添加会成为默认，删除默认不会自动切换其他条目。

升级前停止 API 与 Worker，备份数据库和加密主密钥，执行 `make migrate-up`（至 29），再启动一致的新版本并刷新浏览器。迁移与备份恢复演练仅使用隔离数据库。
