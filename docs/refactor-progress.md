## 验证范围

`./scripts/verify.sh` 在隔离依赖下执行：架构依赖检查、Go 格式检查、`go vet ./...`、`go test -race -count=1 ./...`、TypeScript 类型检查、Prettier、Playwright 与 Vite 构建。MySQL、Redis、SMTP 都使用测试端口 13306、16379、11025；没有真实 LLM 调用。

上述完整检查、迁移恢复演练和容量样本均已在本机通过。最后补充的 AI 供应商错误（502）与存储错误（503）分类、配置响应及错误响应契约，另行通过 AI/契约包竞态测试；随后再次通过 `go vet`、架构检查与 `git diff --check`。

数据库回归包含：并发创建/启用不超过 20 个订阅、旧版本拒绝和无变化不增加版本、订阅与回填任务事务回滚、AI 配置删除重建、真实 AI 执行路径、SMTP 成功但数据库确认失败后的固定内容重试、Redis 数据丢失、五次失败、旧 Collector 执行者拒绝写入、论文/checkpoint 不倒退、回填提交游标后恢复与实时匹配重叠、回填失败及人工重试。

浏览器覆盖 7 个场景：过期页面响应、AI 字段编辑与 409、401 清理会话、503 与重试入口、关闭详情取消轮询、配置删除生命周期 ETag、移动端布局与 Escape 关闭弹窗。使用真实 Chromium 与可控 API 替身；Go 真实数据库 API 测试负责服务端契约，两者不等同于完整生产环境端到端验收。

迁移脚本在单独新建数据库中从 00018 升级，并在 00020 第一条 DDL 后注入故障，确认失败没有被标记为成功；恢复停写前备份后升级至 00024，并核对配置身份、订阅版本及 AI 字段。另行执行从空库到 00024 的初始化。

OpenAPI 使用 3.0.3，以匹配当前 kin-openapi 校验器实际支持的空值语义；响应中的 `objective: null` 纳入动态校验。CI 配置已加入仓库，本轮验证是在本机运行相同检查，不宣称 GitHub 上已执行通过。

## 容量样本（2026-09-10）

机器：Linux x86_64，双路 Intel Xeon Gold 5318Y，96 个逻辑 CPU，约 251 GiB 内存；Go 1.26.5。MySQL 8.4 使用 Docker tmpfs，测试连接池采用集成测试配置；SMTP 使用假发送器，2 个邮件 Worker、100 个队列槽。浏览器环境为 Node 22.23.2 与 Chromium；本机 Ubuntu 20 使用 Playwright Ubuntu 22 构建覆盖值。

数据：1,000 用户、每用户 20 个启用订阅、100,000 篇论文。回填样本匹配 100 篇，501 批（含最终空批），其余邮件任务主要为空候选。

| 指标 | 最终样本 |
|---|---:|
| 20,000 条调度读取 | 94.94 ms |
| 单回填任务遍历 100,000 篇论文 | 1.50 s |
| 20,000 个持久投递任务处理 | 30.66 s |
| 队列等待 P50 / P95（含入队背压） | 153.34 / 162.50 ms |
| Go 堆基线 / 采样峰值 | 8.04 / 22.95 MB |
| 本次负载的 InnoDB 行锁等待次数 / 时间增量 | 0 / 0 ms |

回填查询计划使用 `idx_papers_source_cursor`，无 filesort。此前缺少该索引时，同规模回填出现 2.58–22.23 秒波动；00024 与对应查询消除了本轮观察到的重复窗口扫描问题。

这些是单机合成样本，不覆盖真实 SMTP/LLM 吞吐、生产磁盘持久化成本、2 万个回填任务同时运行、长期混合负载或故障风暴。未据此宣称生产支持目标规模。测试数据会自动清理，容量测试默认不在普通单测中执行。

## 发布边界

新增迁移尚未应用到业务环境。发布必须安排停写窗口，备份并验证恢复，同时切换前端、API 与 Worker；不能混跑旧 Worker。00019/00020/00022 为明确的只前进迁移，生产回退通过已验证备份完成。SMTP 不确定结果自动重试，仍可能重复发送，这是此次方案接受的语义。

没有得到可信覆盖率数字，因此不报告覆盖率百分比；质量门槛依赖上述具体行为验证。
