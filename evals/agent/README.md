# Agent 评测与演示

`cases.jsonl` 包含 30 条订阅需求，以及 10 篇论文各 5 个问题（共 50 个）。案例覆盖正常规则、澄清、非法工具要求、贡献、方法、实验、局限和资料不足。论文标题与 arXiv ID 用作选取材料的清单，不预先假定回答正确。

确定性测试使用假的模型响应与隔离数据库，验证协议、权限、幂等和恢复；真实模型质量评测独立执行。不要把集成测试成功率当作实际模型准确率。

## 真实模型运行

准备专门的评测用户，在页面配置所需供应商。论文需要已进入该用户的匹配列表。创建 JSON 映射文件，例如 `{"1706.03762": 123}`，将清单中的 arXiv ID 对应到本地论文 ID；缺失论文记录为 not_run。

通过环境变量 `SIGNALWATCH_EVAL_TOKEN` 提供评测用户访问令牌，令牌不要写入命令参数或结果文件。运行期间 API 和 Worker 都需启动。订阅每轮最多四次；论文追问案例先生成报告（最多二十四次），再追问（最多三次）；原 80 条案例最多 1470 次，受用户日限额约束。

```bash
python3 scripts/eval-agent.py --provider glm --model glm-4.7-flash \
  --paper-map /tmp/agent-paper-map.json --output /tmp/agent-results.jsonl
```

可以先用 `--kind subscription --limit 3` 验证环境。工具不会确认订阅草案，也不会自动重试不确定的付费请求。评测会在评测账户保存聊天记录；结果文件必须使用新路径，防止覆盖证据。

JSONL 保存真实运行状态、消息、引用、草案和调用步骤；summary 文件统计成功完成数量、P50/P95 延迟及 token。人工逐例填写 `human_review`：

- `draft_correct`：分类、关键词语义和显式偏好是否符合用户要求（订阅案例）。
- `retrieval_hit`：回答实际需要的证据是否在本轮返回片段内（论文案例）。
- `claims_supported`：主要事实是否由引用支持；核对实验数字及条件。
- `insufficient_handled`：资料不足时是否承认边界。
- `notes`：失败原因、期望页码与可复现的修改建议。

未人工审阅的字段保持 null；指标分母仅使用适用且已审阅案例。当前没有在此目录写入虚构的模型质量、成本或性能结论。

## 演示脚本

1. 配置两家供应商，在订阅页描述研究兴趣，观察工具进度。
2. 检查并编辑草案，确认后展示订阅及回填状态；刷新验证没有重复创建。
3. 打开匹配论文的全文对话，提问方法或实验；展开引用并查看原文页码。
4. 切换聊天供应商继续追问，展示默认邮件模型未变化。
5. 刷新恢复历史；展示资料不足、停止运行与明确的错误状态。
6. 用真实评测输出解释成功率、延迟、token 和失败案例；简历只填写已经测量的数据。

## 固定论文报告（工作流 v5）

使用 `--kind paper --report` 为清单中每篇论文生成一份报告（按 arXiv ID 去重）。支持显式 `--credential-id`；短论文通常六次调用，长论文最多二十四次，等待窗口为十六分钟。省略 `--report` 时论文案例先生成成功报告，再运行固定追问流程（追问本身最多三次，合计最多二十七次调用）；订阅案例仍最多四次。

```bash
python3 scripts/eval-agent.py --provider glm --model glm-4.7-flash \
  --credential-id YOUR_EVALUATION_CREDENTIAL_ID --kind paper --report --limit 5 \
  --paper-map /tmp/agent-paper-map.json --output /tmp/paper-report-results.jsonl
```

JSONL 保留结构化报告、字段状态、依据范围、降级原因、证据与实际模型调用数；摘要降级必须单独统计，不能计作全文成功。人工审阅五个字段的事实、实验数字与条件、缺失说明和引用支持情况，记录真实费用与等待时间。`human_review` 在未审阅时保持 null，不以自动语义校验的结果代替人工评分。

报告前置规则：评测脚本不绕过接口限制。前置报告失败时不提交追问；结果单独保存 report_run_id/report_steps，模型调用数和 token 包含前置报告成本。

证据审阅注意：v4 模型只返回片段编号，引文由服务端原样取出。编号有效不代表论断受支持，需阅读整个片段核对条件；PDF 脚注、断词和图表仍可能影响理解。Streaming4D 的真实调用故障与修复验收见 [Agent 架构记录](../../docs/agent-architecture.md)。

语言评测：报告叙述应为中文，专名/缩写/公式及证据原文可保留英文。单独记录整段英文、普通术语未译及中文表述质量；v5 的无汉字检查仅拦截明显偏离，不替代人工语言审阅。英文追问应继续返回英文。
