# 本地真实模型验收（终端输入密钥）

在项目根目录手动运行；不要把密钥写在命令里，也不要把终端调试跟踪打开。脚本不读取 `.env`，不经过 Makefile，所以 `.env` 中的空模型配置不会覆盖本次输入。

## 小样本：默认 3 篇 + 1 组

```bash
python3 scripts/accept-ai-local.py
```

依次输入：

1. GLM 的 **Chat Completions 兼容接口前缀**，程序会追加 `/chat/completions`。请从所用服务控制台复制，不要输入含密钥的 URL，也不要填写完整的 `/chat/completions` 路径。
2. 该服务支持的模型名称。
3. 核对样本数和调用数后输入 `yes`。
4. 隐藏输入 API Key，回车。

默认从本地 `deploy-mysql-1` 容器只读提取最近三篇论文的 ID、标题和摘要，不读取用户、订阅或密码字段，不修改数据库。MySQL 登录使用容器现有的应用账号环境配置，不在日志中输出凭据。

每篇中文摘要一次调用，多篇中文总结一次，共最多 **4 次**。`--language both` 时为 **8 次**。请求逐个执行、单次超时 20 秒、不自动重试；鉴权错误立即停止。某些模型需要额外供应商参数或默认推理耗时较长，脚本会如实呈现当前产品适配器的失败，不擅自绕过产品的协议或时间限制。

## 指定样本或正式扩大规模

```bash
python3 scripts/accept-ai-local.py --count 30 --groups 10 --language zh
```

此配置最多 40 次调用；双语最多 80 次。每次运行最多 200 次。**这是独立验收工具的单次上限，不计入业务 Worker 的 MySQL 每日额度；重复运行会重复调用。请按账户实际账单控制总费用。**

若不使用 Docker，可提供自己的 UTF-8 JSON 数组：

```json
[
  {"id": 1, "title": "第一篇论文的真实标题", "abstract": "第一篇论文的完整原始摘要"},
  {"id": 2, "title": "第二篇论文的真实标题", "abstract": "第二篇论文的完整原始摘要"}
]
```

```bash
python3 scripts/accept-ai-local.py --papers /你的路径/papers.json --count 2 --groups 1
```

多论文组按输入顺序每三篇分组，最后不足两篇时向前补足；可预先排列样本以覆盖同主题、跨主题和无共同主题情况。三十篇/十组配置恰好十组不重叠样本。

## 邮件预览与可选 Mailpit

默认只生成本地文件，不发邮件。若希望在本地 Mailpit 中看实际 SMTP 邮件，显式指定：

```bash
python3 scripts/accept-ai-local.py --mailpit 127.0.0.1:1025
```

地址必须是本机回环地址；固定测试收件人为 `acceptance@example.test`，不使用业务用户邮箱或业务 SMTP 配置。建议使用独立 Mailpit 实例；例如独立实例监听 1125 就传入 `127.0.0.1:1125`。只投递本轮各组的增强/自动回退邮件，强制原文版本始终保存在本地供对比。

## 看结果

默认输出到新目录 `tmp/ai-accept-时间戳/`（已由现有 `.gitignore` 忽略），也可用 `--output` 指定不存在的新目录。目录权限 0700，文件 0600，拒绝覆盖先前验收。

- `report.json`：模型名、调用次数、逐次耗时、结构校验结果、安全错误代码、提供商返回的 token 使用和验证通过的生成内容。`usage_known=false` 表示 token 用量未知，不能把字段中的零当成免费。
- `papers.json`：本轮论文原文，用来核查摘要依据。
- `digest-XX.html` / `.txt`：使用产品模板渲染的每组邮件；仅展示研究主题概览与论文清单；模型输出不合格时省略总结，不恢复长摘要。
- `fallback-XX.html` / `.txt`：强制无 AI 总结的精简邮件，对比用。
- `REVIEW.md`：人工检查清单。中断、鉴权错误或文件写入失败时可能只有部分报告。

单篇解读仍保存在 report.json 中供核查，邮件不再展开它。预览默认使用 arXiv 链接。程序复用产品提示词、HTTP 适配器、JSON/证据校验和邮件模板；它不验证 Worker 调度、共享额度、持久任务或 `delivered_at`。这些已由集成验收覆盖。

**结构成功不代表事实准确。** 请人工检查核心贡献、方法、实验数字是否有原文依据；缺失信息和推断是否标记；研究主题是否只概括本次样本。真实质量通过与否由人工记录，脚本始终把人工审查标记为 pending。

可分享 `report.json`、`REVIEW.md` 和相关邮件预览。不要分享 API Key 或完整环境配置。

## 密钥处理边界

密钥仅在隐藏终端输入后驻留进程内存，通过匿名 stdin 管道交给 Go 程序，不写文件、不放命令参数、不加入子进程环境变量、不放提示词。模型错误响应体不落盘；输出额外替换密钥原文，防止意外回显。临时编译程序在退出后清理。

该方式防止脚本主动记录密钥，但不是操作系统级隔离：有权限的本机调试器仍可能访问进程内存。若要求其他本机进程严格无法接触密钥，应在独立机器/受控环境运行。首次运行只需要 Go、Python 3，以及选择数据库导入时的 Docker/MySQL；不需要安装 Python 第三方包。
